    Retrieval Studio

    Understand your documents. Check every answer.

    Retrieval Studio is a workspace for asking questions about documents you upload. It uses Retrieval-Augmented Generation (RAG): find relevant passages first, then give those passages and your question to a language model to prepare an answer.

    Use it to explore reports, learn from study material, locate requirements, or compare ways to search a document collection. Instead of searching through a long PDF yourself, ask a question and follow the citations back to the supporting passages.

    Evidence you can inspect. The answer shows which documents and pages contributed. Sources opens the supporting passages; Evidence exposes retrieval scores and metadata. Citations help you verify a claim, but do not guarantee that every generated statement is correct.
    Quick start

    From a file to a grounded answer

    1. Add your files in Documents. Upload PDF, DOCX, TXT, Markdown, CSV or JSON. Files are staged in your browser until you choose a chunking technique and select Chunk and index documents.
    2. Choose a chunking technique. Recursive is a useful starting point for general text. Section-based suits clearly structured headings. Parent-child keeps small searchable passages linked to larger context.
    3. Ask in Playground. Select one document or All documents, enter a specific question, and run the query. Hybrid + re-ranking is the recommended starting retriever. Narrow the page range or section with Metadata filters when needed.
    4. Verify and refine. Open a numbered reference, inspect Sources and Evidence, or expand Pipeline overview. Change document scope and rerun to answer from another file.

    Experiment: Compare strategies runs two pipelines against the same question. Choose a specific document to try different chunkers and token sizes. Entire corpus mode uses the chunks already indexed, so its chunking controls are disabled. Chunk explorer lets you browse the stored passages directly.

    Your account keeps its own documents, indexes and saved results. Use Sign out when you finish on a shared device.
    01 / Prepare the knowledge

    Chunking techniques

    Chunking divides extracted text into passages the retriever can search. Smaller chunks can be precise but lose context; larger chunks preserve context but may include unrelated text. A token is a unit of text used by the tokenizer, not necessarily a whole word.

    Recursive character splitting

    Splits at paragraph and line boundaries, then spaces and characters as needed, using token counts to size the chunks. Standard ingestion uses about 500 tokens per chunk with 50 tokens of overlap.

    Advantages
    Predictable sizes, straightforward processing, and a good baseline for mixed prose. Overlap keeps some context across boundaries.
    Trade-offs
    It does not understand topic boundaries. Related ideas may be split, and overlap stores repeated text.

    Best for: general reports, plain text and a first baseline.

    Section-based chunking

    Detects heading patterns such as Markdown headers and numbered sections. Oversized sections are split recursively while retaining section metadata; standard ingestion uses an 800-token section limit.

    Advantages
    Keeps heading context with the passage and makes section filtering useful. Often follows the way a document is organized.
    Trade-offs
    Depends on recognizable headings in the extracted text. Irregular PDF layouts or missing headers can weaken the boundaries; large sections still need splitting.

    Best for: manuals, specifications and clearly headed documents.

    Parent-child chunking

    Creates small child chunks linked to larger parent passages. Standard sizes are 200 tokens for children and 1,000 tokens for parents. Choose Parent-child retrieval to use those links for context expansion.

    Advantages
    Search small passages for precision, then give the model their larger parent context. Multiple hits can resolve to one parent instead of repeating it.
    Trade-offs
    Maintains additional parent data and can send more context to the model. Expansion depends on having ingested parent-child links.

    Best for: answers that need surrounding explanations, not just a matching sentence.

    Custom sizes and overlap are available in document-specific comparisons. The standard upload flow uses the defaults above. Semantic chunking is not implemented in this workspace.

    02 / Find the evidence

    Retrieval strategies

    The chunker decides what is stored; the retriever decides which stored passages are relevant to your question. These are separate choices.

    StrategyHow it worksAdvantagesTrade-offs
    Basic vectorEmbeds the question and finds nearby chunk vectors in ChromaDB using cosine similarity.Useful for meaning, paraphrases and conceptually related language.May miss exact codes or names. Similar meaning is not proof that a passage answers the question.
    Keyword · BM25Ranks passages by weighted query-term matches, term frequency and document length.Useful for exact identifiers, technical vocabulary and phrases containing distinctive keywords.Can miss synonyms and paraphrases when the terms do not match.
    Hybrid searchCombines vector and BM25 rankings with weighted reciprocal rank fusion (RRF).Covers both semantic meaning and exact keyword matches. Search balance controls the two contributions.Runs both search methods and needs sensible weighting. A high merged rank can still be irrelevant.
    Hybrid + re-ranking RecommendedRetrieves a hybrid candidate pool, then a cross-encoder scores each question–passage pair and chooses the final top K.Can improve ordering by evaluating the question and passage together. A strong starting point for answer quality.Adds computation and latency. It cannot recover evidence that never entered the candidate pool.
    Parent-childFinds child passages and expands linked hits to their parent context. Ordinary chunks have no parent context to expand.Preserves surrounding information and reduces repeated parent passages.Larger context can include extra material. Use parent-child ingestion to benefit from expansion.
    Choosing a strategy: start with Hybrid + re-ranking. Try BM25 for a specific code or term, vector search for paraphrases, and parent-child for context-heavy questions. Compare actual answers and evidence; the recommendation is a starting point, not a universal winner.
    03 / Build and inspect the answer

    What happens inside the pipeline?

    Local embeddings
    all-MiniLM-L6-v2 turns passages and questions into 384-dimensional vectors. It enables meaning-based search locally after model setup; embedding similarity is only a retrieval signal.
    Reciprocal rank fusion
    Combines ranked vector and BM25 results rather than directly comparing incompatible raw scores. The hybrid implementation uses an RRF constant of 60. The Search balance slider supplies the semantic and keyword weights; it affects hybrid-based retrieval.
    Cross-encoder re-ranking
    ms-marco-MiniLM-L-6-v2 scores question–passage pairs locally after hybrid retrieval. It trades extra processing time for a more focused final ordering.
    Metadata filters
    Document scope restricts retrieval by source filename. Page ranges, exact sections and chunking strategy can further narrow it; supplied conditions are combined with AND. A narrow filter may return no evidence. Same-name uploads share a source filter.
    Top K and context assembly
    Top K controls how many final passages are requested. The backend assembles context and numbered citations for the model. More passages can increase coverage but also add noise and generation cost.
    Answer generation
    The configured Gemini model reads your question and retrieved context. The current default is gemini-3.1-flash-lite. Relevant text is sent to the configured external model provider for generation. If generation is unavailable, the app labels a local extractive fallback that shows material from the retrieved passages.
    Traces and comparisons
    Execution details show measured step durations and errors. Compare strategies reports answers, evidence and execution latency; its timing excludes temporary index preparation. Retrieval scores are method-specific and are not faithfulness percentages. Trace token counts are estimates, not provider billing totals.
    Built with

    The tech stack behind this workspace

    These are the components used by the running application, rather than everything listed as a possible dependency.

    Interface
    HTML, CSS and vanilla JavaScript, served by FastAPI from the same origin. Locally bundled Marked renders Markdown; DOMPurify sanitizes the resulting answer markup. The integrated interface does not require a frontend build.
    API and validation
    Python, FastAPI and Uvicorn serve the API. Pydantic validates uploads, queries and comparison settings. LangChain components handle text splitting and the prompt–model–output generation chain.
    Models and retrieval
    Gemini with the Google GenAI/LangChain integration for configured answer generation; Sentence Transformers and PyTorch for local embeddings and cross-encoder models; rank_bm25 for lexical search; ChromaDB for vector storage.
    Document parsing and tokenization
    pypdf extracts PDF text, python-docx reads Word content, and text-based formats are parsed by the ingestion service. tiktoken supports token-aware chunk sizing.
    Accounts and persistence
    Email/password accounts use salted scrypt password hashes and HttpOnly session cookies. Per-account storage keeps document state, vector indexes, history and saved answers on the server. The local deployment uses filesystem/JSON state and ChromaDB persistence; it runs with one worker.
    Verification
    Pytest and HTTPX test backend behavior. Node’s test runner and jsdom test frontend behavior such as document scoping, answer formatting and citation navigation. Managed-browser checks validate real user flows.
    Practical help

    Get better results

    Why is the answer coming from a different document?

    Choose a specific file in Playground’s Document scope selector. All documents may combine passages from several files. Check Answer scope and Sources used. After changing scope, run the query again; an earlier answer keeps its original scope label.

    Why are no matching passages found?

    Check the selected document and metadata filters. Try a more specific question, alternate terms, or a different retriever. A scanned PDF may contain no extractable text: this app does not perform OCR. Do not treat an empty result as proof that the original document has no answer.

    Why is a query slow, or why did I get an extractive response?

    Re-ranking and model generation add time; local model initialization can also take time. Provider availability and rate limits affect generation. An extractive fallback is labeled in the answer; execution details show the provider error when available.

    What does this workspace not implement?

    It does not currently implement semantic chunking, HyDE, multi-query expansion, step-back prompting, streaming answers, or a RAGAS evaluation dashboard. Comparisons do not report faithfulness, relevancy, precision or recall benchmarks. Dependencies or assignment requirements mentioning a technique do not mean it is available here.

    Are uploaded files used to train a model?

    The ingestion flow indexes extracted passages for retrieval; it does not fine-tune a model. For generation, your question and selected context are sent to the configured provider. Provider retention and data-use terms are separate from this app’s indexing behavior.

    Useful keyboard shortcuts

    Ctrl / ⌘ + K opens Playground and focuses your question. Ctrl / ⌘ + Enter runs the query when no dialog is open. Use the arrow keys to move between Answer, Sources and Evidence tabs.
